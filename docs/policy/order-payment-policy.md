# Order Payment Policy

주문/결제 정책은 포인트 차감, 주문 생성, 결제 생성이 일관되게 처리되도록 하는 기준이다.
주문/결제 흐름에서는 데이터 정합성을 우선한다.

## 기본 규칙

- 사용자는 로그인한 상태에서만 주문할 수 있다.
- 주문 요청에는 메뉴 ID만 입력받는다.
- 주문 금액은 클라이언트가 입력하지 않는다.
- 주문 금액은 서버에 저장된 메뉴 가격을 기준으로 한다.
- 판매 중단된 메뉴는 주문할 수 없다.

## 주문 규칙

- 메뉴가 존재하지 않으면 주문을 생성하지 않는다.
- 메뉴 상태가 `ACTIVE`가 아니면 주문을 생성하지 않는다.
- 주문 생성 시 주문 금액은 주문 당시 메뉴 가격으로 저장한다.
- 주문 상태는 주문 성공 시 `COMPLETED`로 저장한다.

## 결제 규칙

- 결제는 포인트로만 가능하다.
- 결제 금액은 주문 금액과 동일해야 한다.
- 포인트 잔액이 부족하면 결제와 주문은 생성되지 않는다.
- 결제 성공 시 결제 상태는 `COMPLETED`로 저장한다.

## 트랜잭션 규칙

- 포인트 차감, 포인트 사용 이력 저장, 주문 저장, 결제 저장은 하나의 트랜잭션으로 처리한다.
- 트랜잭션 중 하나라도 실패하면 전체 작업을 롤백한다.
- 포인트만 차감되고 주문 또는 결제가 저장되지 않는 상태가 생기면 안 된다.
- 주문 또는 결제만 저장되고 포인트가 차감되지 않는 상태가 생기면 안 된다.

## 동시성 규칙

- 같은 사용자가 동시에 여러 주문을 요청할 수 있다.
- 같은 포인트 잔액을 동시에 차감하면 중복 차감 또는 음수 잔액 문제가 생길 수 있다.
- 포인트 차감 시에는 동시성 제어를 적용해야 한다.
- 정확성이 성능보다 중요하므로 비관적 락을 우선 고려한다.

## Kafka 이벤트 규칙

- 주문 결제가 완료되면 `PaymentCompletedEvent`를 발행한다.
- 이벤트에는 사용자 ID, 메뉴 ID, 주문 ID, 결제 ID, 결제 금액, 결제 완료 시간이 포함되어야 한다.
- Kafka 이벤트는 인기 메뉴 집계 또는 외부 데이터 수집 플랫폼 전송에 사용할 수 있다.
- Kafka 이벤트 발행 실패 시 주문/결제 트랜잭션에 어떤 영향을 줄지 정책으로 명확히 기록해야 한다.
