# Generate Guide

Generate 단계는 승인된 Plan을 기준으로 실제 코드를 작성하는 단계다.

## 목적

- 계획된 범위 안에서 기능을 구현한다.
- 기존 코드 스타일과 패키지 구조를 따른다.
- 구현 과정에서 생긴 판단을 기록한다.

## 절차

1. 승인된 Plan을 다시 읽는다.
2. 관련 코드와 정책 문서를 확인한다.
3. 계획 범위 안에서 파일을 생성하거나 수정한다.
4. 공통 응답, 예외 처리, 트랜잭션 규칙을 따른다.
5. 구현 후 변경 파일과 동작 흐름을 정리한다.
6. 계획에서 벗어난 변경이 생기면 이유와 영향을 `docs/ongoing/` 문서에 기록한다.

## 코드 작성 기준

- 공통 응답은 `CommonApiResponse`를 사용한다.
- 예외는 `CustomException`과 `ErrorCode`를 사용한다.
- 비즈니스 로직은 Service에 둔다.
- 데이터 접근은 Repository에 둔다.
- DTO와 Entity의 책임을 섞지 않는다.
- API 계약을 바꾸면 `docs/api/README.md`를 함께 수정한다.
- 테이블 또는 Entity 계약을 바꾸면 `docs/db/README.md`를 함께 수정한다.
- 도메인 판단을 바꾸면 `docs/policy/` 문서를 함께 수정한다.

## 구현 기록 템플릿

```md
## Generate 기록

- 구현일: YYYY-MM-DD
- 수정 파일:
- 변경 요약:
- 계획 대비 변경된 점:
- 결정 사항:
- 다음 Evaluate 대상:
```

## 금지 사항

- 승인되지 않은 범위까지 구현하지 않는다.
- 요구사항과 무관한 리팩터링을 하지 않는다.
- 기존 사용자 코드를 임의로 삭제하지 않는다.
