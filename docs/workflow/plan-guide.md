# Plan Guide

Plan 단계는 코드를 작성하기 전에 작업 범위와 검증 기준을 정하는 단계다.

## 목적

- 요구사항을 기능 단위로 해석한다.
- 관련 문서와 기존 코드를 먼저 확인한다.
- 변경 대상과 영향 범위를 정리한다.
- 구현 전에 통과 기준을 정한다.

## 절차

1. 사용자 요청을 기능 단위로 나눈다.
2. 관련 도메인 패키지와 파일을 확인한다.
3. 기존 Entity, Repository, Service, Controller, DTO 구조를 읽는다.
4. 변경 대상 파일과 예상 영향 범위를 정리한다.
5. 구현 방향을 짧게 작성한다.
6. 테스트 또는 검증 기준을 정한다.
7. 필요한 경우 `docs/ongoing/{작업명}.md`에 계획을 남긴다.

## 산출물

- 작업 요약
- 변경 대상
- 접근 방향
- 통과 기준
- 남은 질문 또는 리스크

## 금지 사항

- Plan 단계에서 코드를 작성하지 않는다.
- 확인하지 않은 클래스, 메서드, 필드를 있다고 가정하지 않는다.
- 구현 세부사항을 과도하게 확정하지 않는다.
